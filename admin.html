Read is zero-PII (wallets + USD only).

Read a wallet from your private registration Sheet, paste it here, and sign the presale voucher with this wallet (must be the sale's allowlistSigner). The signature proves nothing personal — the published allowlist.json holds only addresses + signatures. Publishing = committing that file. Batch supported; a rejected sign never halts the rest.

Robot Registry — approval-bot status

Read-only window into the automated approval service. Fetches the bot's own state projection (GET /registry, bearer-gated) — never signs, never sends, never publishes. The projection carries no signatures and no verify tokens. Use it to watch the queue, catch OFAC holds, and see duplicate clusters. The manual Approve Buyers panel above stays your fallback.

Drop Desk — sign & publish drop coupons

Hand-sign one-time drop coupons with this wallet (must be the desk's dropSigner). Each coupon is signed EIP-712 DropCoupon(wallet, amount, deadline, nonce) with a fixed 90-day deadline baked in. The published coupons.json holds only address, amount, deadline, nonce, signature — zero personal data. Publish either way: Publish via robot (the robot verifies each signature + deadline and commits coupons.json), or Download the file and commit it by hand (fallback). Fund the desk by a plain DYC transfer from the ecosystem allocation; withdraw unspent balance with the contract's withdraw.

Voiding is a 48-hour governance act. DropDesk.cancel() is owned by the Timelock — it cannot be sent from this signing wallet. To void an unclaimed coupon, propose and execute cancel(nonce) through governance (48-hour delay); a redeemed coupon is final. This control stays disabled on purpose, so the button never pretends to work.

Process Claim — Grant Rewards

Users request their staking rewards by email; grant them here. This calls HolderStaking.creditRoi(wallet, amount) — the admin wallet must be a registered debitor (owner sets that via the timelock at go-live) and must hold DYC. creditRoi pulls DYC from this wallet, so the flow approves DYC to the staking contract first, then grants. Grants are in multiples of 1,000 DYC only — anything else is refused before any transaction.
